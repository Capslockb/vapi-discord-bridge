  This is a source-verified map of plugin/bridge.py. It is not a complete
  reference for every event supported by Vapi.

  CALL SETUP
  ──────────

  1. POST https://api.vapi.ai/call with Bearer authentication.
  2. Request transport provider "vapi.websocket" with:

     {
       "audioFormat": {
         "format": "pcm_s16le",
         "container": "raw",
         "sampleRate": 16000
       }
     }

  3. Read transport.websocketCallUrl from the response.
  4. Append /transport only when the returned path does not already end with it.
  5. Open the returned WebSocket URL. Do not log or publish that URL.


  OUTBOUND — bridge → Vapi
  ────────────────────────

  AUDIO

     Raw binary PCM bytes
     - signed 16-bit little-endian
     - mono
     - 16 kHz
     - normally produced from decoded Discord 48 kHz stereo audio

  When no user audio is queued, the active keepalive loop sends a raw 20 ms
  silence chunk. Audio is not wrapped in base64 JSON.

  TEXT INJECTION

     {
       "type": "text",
       "text": "Reminder: standup in 5 minutes"
     }

  This path is used by voice_vapi_say, the loopback /say route, and the idle
  prompt.

  NOT SENT BY THE CURRENT RUNTIME

     - a manual JSON "start" frame;
     - a manual JSON "stop" frame;
     - function-call-result messages.


  INBOUND — Vapi → bridge
  ────────────────────────

  AUDIO

     Raw binary PCM bytes
     - treated as signed 16-bit little-endian
     - mono
     - 16 kHz
     - resampled to Discord 48 kHz stereo for playback

  STRING JSON MESSAGES

     assistant-started
       Logs the assistant name.

     conversation-update
       When status is "interrupted" or "ended", clears buffered playback if
       DISCORD_VAPI_CLEAR_ON_INTERRUPT is enabled.

     transcript
       Reads the text field. If it contains "disconnect", requests bridge
       shutdown.

     all other JSON
       Logged at debug level only; no feature dispatch occurs.

  NOT IMPLEMENTED BY THE CURRENT RECEIVE LOOP

     - transcript JSONL persistence;
     - Vapi function/tool-call dispatch to Hermes;
     - sending function-call results back to Vapi.

  These gaps are tracked in:
  https://github.com/Capslockb/vapi-discord-bridge/issues/2
